# 阶段 A 样张与核验记录

日期：2026-09-27。范围：一份完整的中文校招样张，一个墨蓝主风格。本文件记录阶段 A 的设计和核验；当前实现与输出请查看阶段 C 记录。

## 设计选择

- 单栏保持连续阅读顺序；教育、技能、实习、项目、其他信息依次排列。
- 左侧独立证件照 23 × 31 mm；右上角学校 Logo 容器 34 × 25 mm。Logo 透明背景、等比 contain；照片独立 cover。
- 中部姓名、目标岗位和联系方式形成页眉主体，不与图像重叠。
- 四周 15 mm；正文 10.5 pt、1.36 行高；姓名 23 pt；章节标题 11.8 pt。
- 标题和少量关键指标加粗，日期用较小灰色字右对齐；不使用技能进度条、评分或大色块。
- 页脚明确说明所有资料、指标及人像均为演示，避免将合成经历误当成真实求职材料。

## 实际迭代

第一版真实 PDF 为两页，第二个项目和其他信息溢出。经渲染两个页面后发现，角色单独占行和重复的项目叙述耗费较多空间。将角色并入条目标题行，收紧少量模块间距，精简冗余叙述；保留 10.5 pt 正文与技术指标的实验条件，没有通过整体缩放强塞进一页。

一页版文字核验又发现：原 Noto Sans SC 可变字体在当前 Chromium 中导出为大量 Type 3 字体，部分汉字的 ToUnicode 映射为形似的兼容部首，例如“项目”的“目”。已改为固定字重并移除重复部首别名，重新导出后为三个带 ToUnicode 的嵌入 CID TrueType 字体，原始文字提取可找到“项目经历”，无需靠 Unicode 归一化掩盖错误。

## 最终 PDF 核验

构建环境：Node.js 24.18.0；Playwright 1.63.0（锁定依赖）；Chromium 153.0.8010.12。首次准备依赖之后，构建使用浏览器离线模式。实际请求中没有 HTTP/HTTPS 资源。

| 检查 | 结果 |
| --- | --- |
| 页面 | 1 页，A4，594.96 × 841.92 pt |
| 正文 | 10.5 pt，未缩放，内容高 998.0 px / 可用 1009.1 px |
| 顶部图片 | 两个独立图片对象，学校 Logo 位于右上角，照片在左侧 |
| 字体 | Regular / SemiBold / Bold，均嵌入，均有 ToUnicode |
| 中文与技术词 | 对内容模型的全部 49 个可见文本字段逐项比对通过，覆盖中文、技术词与指标；不进行 Unicode 归一化修饰 |
| 阅读顺序 | 姓名 → 教育 → 技能 → 实习 → 项目 → 其他 → 演示说明 |
| 链接 | 电话、邮件、示例作品集共三个链接，目标与内容模型一致 |
| 页面边界 | 文本位于安全区域；没有横向溢出；没有第二页或空白页 |
| 最终视觉检查 | Poppler 将最终 PDF 渲染至 150 DPI PNG；检查完整页面及顶部、正文局部，没有缺字、重叠或裁切 |

阶段 A 首轮核验包括真实 PDF、页面 PNG、布局测量和文字提取。当前 `output/pdf` 已由 Markdown 链路重新生成，采用按样张命名的 `*.metrics.json`、`*.verification.json`，最新完整证据见阶段 C 文档。视觉检查和文字检查独立进行，HTML 的截图不作为 PDF 核验替代品。

## 当前边界

阶段 A 用结构化 JSON 打磨视觉；Markdown/YAML 解析、正式字段 Schema、输出路径选择与通用 CLI 尚未实现。图片槽位固定，只有本次双图片样张经过最终 PDF 视觉验收。两页输出、更多图片组合、极长标题及内容增减属于阶段 C，尚未宣称通过。

CSS 已为章节标题设置避免孤立在页尾的规则，但阶段 A 构建器会明确拒绝超出一页，不把草案规则当作两页排版已验收。只复用本仓库的代码与资源，没有修改其他会话的目录或依赖。
