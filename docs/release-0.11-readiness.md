# v0.11.0 发布准备

本轮以正式版本号 `0.11.0` 的 Windows 免安装包为候选，串联已合并的保存失败提示、未保存草稿下载、自动草稿恢复与错误定位功能。测试使用隔离数据目录和匿名样例；尚未公开 v0.11.0 正式 Release。

## 用户流程

通过真实启动程序与包内 Node、Chromium 执行，移除系统 Node 的 PATH，禁止外部请求并使用失效网络代理。完成首次启动、校招起步选择、表单错误定位、姓名与岗位填写、23:31 照片裁剪、独立学校 Logo、PDF 下载、单份备份与恢复、外部修改冲突、草稿 ZIP、关闭并重新启动后的草稿选择、明确恢复、复制简历、整库备份与恢复和小屏填写。

保存冲突保留正式文件和页面输入；恢复到编辑区后继续检查冲突。明确选择 ZIP 恢复前，先重新载入最新资料，恢复时保留原版本。最终再次启动后，选中的简历与填写内容仍在，已有资料不重复显示首次引导。

记录见 `tmp/packages/user-journey-smoke.json`，十个步骤的截图和三份 PDF 在 `tmp/pdfs/user-journey/`。CI 的 Windows 验证保存报告、PDF 和步骤截图；逐页 Poppler 渲染及视觉复核在本地完成。

## 升级验证

升级基线为 GitHub 公开的 v0.10.0 Windows ZIP，实际 SHA-256 为 `d4e07ab9f02702323ee94f1e67b4558a2a874d821c1b582b2fd849c79de25c60`，同时与 GitHub 资产摘要及公开校验文件一致。

候选首次读取旧资料前后，37 个原始数据文件逐项一致；编辑选中的简历后，另外 26 个原文件保持不变。三份在用简历、一份回收站资料、当前选择、独立图片与历史均保留。单份和整库恢复、撤销整库恢复、旧程序重新打开，以及新版再次启动通过。

本地报告是此次实际计数，后续候选与 CI 读取各自报告，不固定文件数量。候选 ZIP 的 SHA-256 记录在两个报告中，用于绑定具体安装包。

## PDF 和视觉检查

用户流程的三份 PDF 各一页；升级验证的三份 PDF 分别为一页、两页、两页，共八页。核对文字、字体嵌入、链接、图片和页面边界，并用 Poppler 逐页渲染查看。姓名保持奶龙；照片保持 23:31，Logo 使用独立槽位，恢复与升级后排版正常。两页输出保留原字号及续页标识。

第二页较空的升级样例用于明确触发分页，应用提示仍以实际内容为准，不自动压缩字号或改写正文。正式候选的八页渲染图与前一轮已逐页复核的图像完全一致。十个步骤截图用于界面复核，不据此承诺完整的无障碍或所有 ATS 兼容。

## 正式版本候选

版本号与锁文件统一为 `0.11.0`；正式版本号的 Windows 包已重新完成启动、完整用户流程、升级及 PDF 验证。其余平台下载包由同一候选提交的六项 CI 构建验证，再用对应报告及 SHA-256 组装发布草稿。

发布组装同时核对升级与用户流程报告的版本、实际 Windows ZIP 摘要和完整验收结果，写入 `release-validation.json`；中文报告明确按 UTF-8 读取，并验证非 UTF-8 默认编码环境。草稿标题使用 `v0.11.0 - 草稿保护与恢复`，说明、归档与下载清单一致后集中发布。草稿准备期间，公开下载入口继续指向 v0.10.0，公开后再更新。
